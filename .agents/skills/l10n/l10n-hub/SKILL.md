# Localization (l10n & i18n) Architecture Hub

## 1. Overview & Architectural Philosophy

The localization system in `lib/l10n/` provides type-safe, compile-time verified internationalization across all supported locales using Application Resource Bundle (`.arb`) files and `flutter_intl` (`intl_utils`).

### Core Laws of Localization:
1. **Single Source of Truth (ARB Files):**
   - ARB files (`lib/l10n/intl_en.arb`, `lib/l10n/intl_uk.arb`) are the **ONLY** source of translated strings.
   - Modifying copy requires editing ARB files first and running code generation (`flutter pub run intl_utils:generate`). Never edit `lib/l10n/generated/` manually.
2. **Strict Clean Architecture Boundaries:**
   - **Domain Layer:** Strictly framework-agnostic (pure Dart). MUST NOT import `BuildContext` or `S` / `AppLocalizations`. Domain returns typed `DomainFailure` states, enums, or error codes.
   - **Data Layer:** Returns raw server error DTOs or maps them to Domain Failures. Never performs localization.
   - **Presentation Layer:** The **ONLY** layer that resolves Domain Failures, enums, and UI keys into localized strings via `context.localization` or UI extensions.
3. **Zero Manual String Concatenation:**
   - Strictly **PROHIBITED** to construct sentences via string concatenation (e.g. `'$greeting $userName'`). All dynamic data must use ICU placeholders and ICU plurals in ARB.
4. **Slavic Grammar Support:**
   - Ukrainian and Slavic languages require `few` and `many` plural forms in addition to `one` and `other`.

## 3. Directory Structure Standard

```text
lib/
├── l10n/
│   ├── generated/                   # EXCLUDED from manual edits (generated by intl_utils)
│   │   ├── l10n.dart                # Generated S class with S.delegate and S.of(context)
│   │   ├── intl/
│   │   │   ├── messages_all.dart
│   │   │   ├── messages_en.dart
│   │   │   └── messages_uk.dart
│   ├── intl_en.arb                  # English base template (source of truth)
│   └── intl_uk.arb                  # Ukrainian localization
├── presentation/
│   ├── ui_utils/
│   │   └── extensions/
│   │       ├── build_context_localization_extension.dart  # context.localization getter
│   │       └── domain_failure_localization_extension.dart # DomainFailure -> String mapping
│   └── state_management/
│       └── locale/                                        # Dynamic runtime locale switching
│           ├── locale_cubit.dart
│           └── locale_state.dart
```

  enabled: true

  main_locale: en

## 5. Anti-Patterns (Strictly Prohibited)

| Anti-Pattern | Severity | Corrective Action |
| :--- | :--- | :--- |
| Hardcoding raw user-visible strings in UI widgets (`Text('Hello')`) | **CRITICAL** | Extract string to `intl_en.arb` / `intl_uk.arb` and access via `context.localization`. |
| Importing `S` or `BuildContext` in `lib/domain/` or `lib/data/` | **CRITICAL** | Return pure Domain Failures/enums; resolve to localized strings in Presentation. |
| Concatenating translated fragments (`'${context.localization.welcome} ${name}'`) | **CRITICAL** | Use ICU placeholder `"{userName}"` in a single ARB key. |
| Manually editing files in `lib/l10n/generated/**` | **CRITICAL** | Edit `.arb` files and regenerate via `flutter pub run intl_utils:generate`. |
| Omitting Slavic plural categories (`few`, `many`) in Ukrainian ARB | **HIGH** | Provide full ICU plural cases (`=0`, `=1`, `few`, `many`, `other`). |

## 6. Master Verification Checklist

- [ ] All user-facing strings are defined in `lib/l10n/intl_en.arb` and `lib/l10n/intl_uk.arb`.
- [ ] Code generation executed cleanly via `flutter pub run intl_utils:generate`.
- [ ] Domain and Data layers contain zero localization or `BuildContext` imports.
- [ ] `MaterialApp.router` configures `localizationsDelegates: [S.delegate, ...]` and `supportedLocales: S.delegate.supportedLocales`.
- [ ] Strings accessed in UI exclusively via `context.localization.<key>`.
- [ ] Dates and numbers formatted using `DateFormat` / `NumberFormat` with active locale.
